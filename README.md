# 积分小账本 · 微信小程序

可导入微信开发者工具的第一版项目，使用**原生小程序 + 微信云开发**。所有用户界面使用“积分”。保险计算器尚未实现。

## 已实现

- 微信身份建档、自填昵称；账号不依赖昵称，修改昵称不会换账号。
- 房主创建牌局，生成四位随机邀请码，保留前导零；有效期为 24 小时，房主可更新。
- 输入邀请码后申请加入，房主批准后才可读取该局记录。
- 玩家登记积分，房主确认或拒绝。只有已确认的登记计入次数和累计投入。
- 可选结束积分，由玩家提交、房主确认；积分变化 = 结束积分 − 累计确认投入。结束积分可为 0。
- 房主可撤销已确认记录，原记录、确认时间和撤销原因保留。已确认结束积分时，须先撤销结束记录再更正投入。
- 房主结束并归档牌局；历史长期保留在数据库中，不再允许修改。
- “我的牌局”仅查询本人已加入的牌局。第一场 ABCD、第二场 ABCE 时，D 无法查看第二场，E 无法查看第一场。

## 先在微信开发者工具运行

### 1. 导入整个项目目录

解压导入包，或下载本仓库。微信开发者工具 → **导入项目**，选择包含 `project.config.json` 的根目录，不要只选择 `miniprogram/`。

导入时填入你自己的 AppID。仓库里的 `touristappid` 是占位值，真实微信身份和云开发测试必须使用真实 AppID。也可直接修改 `project.config.json` 的 `appid`。

项目已声明 `miniprogramRoot` 和 `cloudfunctionRoot`，无需手动复制每个页面，也无需为前端执行 npm 构建。

### 2. 填写云环境 ID

编辑 `miniprogram/config.js`：

```js
module.exports = {
  envId: '你的云开发环境ID'
};
```

使用与该 AppID 关联的云环境。这里填写环境 ID，不需要填写 AppSecret，也不要把密钥放进项目。

### 3. 创建数据库集合并设置权限

在云开发控制台创建下面五个集合，名称须完全一致：

| 集合 | 用途 |
| --- | --- |
| `users` | 微信身份对应的玩家档案 |
| `rooms` | 牌局、参与者、加入申请与积分明细 |
| `invite_codes` | 四位邀请码与当前牌局的映射 |
| `memberships` | 玩家参与过的牌局索引 |
| `rate_limits` | 加入尝试与创建邀请码的限流计数 |

**每个集合都设为客户端不可读、不可写。** 可以在控制台选择对应权限，或使用 `database/security.rules.json` 中的自定义规则：

```json
{
  "read": false,
  "write": false
}
```

云函数通过服务端 SDK 访问这些集合，客户端只能调用云函数。不要为解决权限报错而把数据库改成公开读写。

在 `memberships` 创建一个非唯一复合索引：

| 字段 | 排序 |
| --- | --- |
| `userId` | 升序 |
| `joinedAt` | 降序 |

索引名可设为 `user_history`。`database/collections.json` 只是创建清单，不会自动部署集合或权限。

### 4. 部署云函数

1. 在开发者工具的云开发面板选择上述环境，确保云函数根目录关联到了该环境。
2. 对 `cloudfunctions/gameApi` 目录点击右键，选择 **上传并部署：云端安装依赖**。
3. 使用平台支持的 Node.js 18 或以上运行时；超时建议设为 20 秒。
4. 部署完成后，检查云端函数名为 `gameApi`，并且部署到了 `config.js` 指定的同一环境。

依赖已在 `cloudfunctions/gameApi/package-lock.json` 锁定。无需把本机 `node_modules` 复制到开发者工具里。

### 5. 编译和预览

点击“编译” → 首页“微信登录并设置昵称” → 保存昵称 → 返回首页创建牌局。

本项目使用云开发登录上下文识别微信身份，不需要额外自建 `wx.login → code2Session` 服务，也不需要在前端放置 AppSecret。所有请求由云函数的 `cloud.getWXContext().OPENID` 决定调用者身份。

**本地编译不等于真实微信联调。** 当前自动化测试未连接你的云环境；首次部署后，需要按下面的流程使用真实微信账号测试。

## 建议的第一次真机测试

1. 用 A 的微信进入小程序，设置昵称，创建第一场。记下四位邀请码。
2. 用 B 的微信输入邀请码。B 此时只能看到申请状态，不能读取牌局名单或积分。
3. A 在牌局详情批准 B 加入，B 等待页面会自动进入详情。
4. B 提交 1,000 积分。确认前累计投入仍为 0；A 确认后，B 的登记次数为 1、累计投入为 1,000。
5. B 再登记一次 500 积分，确认后应为 2 次、1,500 积分。重复点击确认不能重复计数。
6. 如需结果，B 提交结束积分 1,200，A 确认后显示积分变化 −300。结束积分 0 也应正确显示。
7. 让 C、D 加入第一场；第二场只让 A、B、C、E 加入。D 的历史只有第一场，E 的历史只有第二场。
8. A 处理所有待确认积分后结束第一场，邀请码失效，参与者仍可从“我的牌局”打开归档记录。

多个真实微信账号测试时，按微信后台要求添加开发者或体验成员。不要给云函数增加可伪造的 OPENID 测试入口。云函数控制台直接测试可能没有微信调用上下文，返回 `UNAUTHENTICATED`；应从小程序页面发起功能测试。

房主自己的积分记录也要在“待确认积分”中确认。其他玩家不能代替房主审批。

## 项目结构

```text
project.config.json          开发者工具入口；替换 AppID
miniprogram/
  config.js                  填写云环境 ID
  app.js / app.json / app.wxss
  pages/home/                创建、邀请码入口
  pages/join/                等待房主批准
  pages/room/                积分、审批、成员和归档
  pages/history/             我的牌局历史
  pages/profile/             昵称与记录规则
  utils/                     云函数调用和显示格式
cloudfunctions/gameApi/
  index.js                   真实云 SDK 入口
  handler.js                 身份校验与错误响应
  domain.js                  权限、积分和状态流转
  cloud-store.js             事务和数据库适配器
database/                    集合、索引及权限清单
tests/                       业务、权限、适配器和页面渲染测试
docs/architecture.md         数据模型与状态约束
```

## 本地自动化验证

本地业务测试需要 Node.js 18+；WXML/WXSS 编译工具会使用系统对应的官方 WCC/WCSC 包装器。

```bash
# 在项目根目录执行
npm ci
npm test
npm run check

# 需要在本地加载真实云函数 SDK 时安装服务端依赖
npm ci --prefix cloudfunctions/gameApi --omit=dev
```

`npm test` 使用可回滚的内存事务替身和微信公开 WXML 编译器，覆盖权限隔离、并发重复请求、积分状态、邀请码和页面条件渲染；不假装进行真实云登录。`npm run check` 检查 JS、JSON、路由、事件绑定和所有 WXML/WXSS 的本地编译。

在云工作区需要重新导出导入包时，可执行 `python3 scripts/package-project.py`，输出到 `dist/points-table-miniprogram.zip`。导出包排除依赖目录和本机私有配置；解压后选择内部包含 `project.config.json` 的目录导入。

## 排查问题

| 表现 | 检查 |
| --- | --- |
| 首页显示服务尚未配置 | 填写 `miniprogram/config.js` 的 `envId`，重新编译 |
| 云函数找不到或连接失败 | 核对真实 AppID、环境绑定、函数名 `gameApi` 与部署环境 |
| 登录或创建失败，返回服务暂不可用 | 检查五个集合是否创建、运行时及云函数日志中的错误代码 |
| 历史查询失败 | 检查 `memberships` 的复合索引是否创建完成 |
| 没有加入申请或积分申请的即时通知 | 页面使用轮询：申请页约 5 秒、牌局约 8 秒；也可手动刷新 |
| B 不能进入牌局 | A 必须先批准 B 加入；批准积分与批准加入是两种操作 |
| 不能结束牌局 | 房主必须处理完所有待确认积分；加入申请会在归档时自动拒绝 |
| 结束积分未登记 | 这是可选记录，未登记时积分变化显示“未登记”，不会误算为零 |

## 当前边界

- 每局最多 20 位玩家、500 条积分记录（含结束和撤销记录）、100 条加入申请。第一版将单局状态保存在一个文档中，以云数据库事务保障一致性；不是大规模并发系统。
- 邀请码尝试每个账号每分钟最多 5 次。四位码不是访问权限；通过房主批准的参与关系才是权限依据。
- 每次历史加载 20 场，支持继续加载。加入时间排序的偏移分页在同时加入新牌局时可能移动，刷新后可重新获取。
- 房主可撤销已确认记录并保留痕迹；归档不可撤销，也不允许删除历史参与关系。
- 结束积分只是积分记录，不包含支付、兑换或资金结算逻辑；保险计算器尚未实现。
- 上线前仍需真实微信联调、体验成员验证，并按实际数据用途完善隐私保护指引、数据保存与删除流程、昵称和名称的内容安全处理、主体类目及平台审核。更改显示名称不替代业务审核。
